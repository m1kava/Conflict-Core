# Contributing

## Workflow

1. Branch from `develop`: `feature/<name>` or `fix/<name>`.
2. Run `npm run check` (typecheck, lint, formatting, tests, data validation) before pushing.
3. Open a PR; CI must be green.
4. For major features: read the existing architecture, write the design in the PR, implement the smallest clean
   version, add tests, profile if performance-sensitive, check touch controls and multiplayer behaviour, update docs.

## Conventions

* TypeScript strict mode everywhere; ESLint and Prettier are enforced in CI.
* `packages/shared` must not import client or server code. The server never imports DOM or Three.js. UI code never
  contains game rules.
* **Balance values belong in `packages/shared/data/*.json`**, never in code. Named constants for everything else.
* Simulation code: no `Math.random()`, no `Date.now()`/wall clock, no iteration over unordered collections whose
  order could vary; use `world.rng` and entity insertion order. The determinism test must stay green.
* Network: clients send intents only. Every new message gets a strict parser and tests for malformed input. Bump
  `PROTOCOL_VERSION` on any wire change.
* Rendering: no per-unit draw calls (use instanced pools), no allocations in per-frame paths, pool effects.
* Small focused modules; comments explain *why*. No commented-out code.
* Mark features in docs as IMPLEMENTED / PARTIAL / PLACEHOLDER / PLANNED; never present placeholders as finished.

## Assets

All current art and audio is generated by code. Any added asset must follow [docs/ASSET_PIPELINE.md](docs/ASSET_PIPELINE.md)
and be recorded in [docs/ASSET_LICENSES.md](docs/ASSET_LICENSES.md).
